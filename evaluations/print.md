# Print evaluation briefs

Status: prepared, not behaviorally run. Structural checks do not establish design quality.

Run each brief with the same model/tools first without the skill, then with `aoe-print`, in separate contexts. Do not give the evaluator the expected checks before producing its result. Compare artifacts blind where possible. Record model/version, supplied assets, output, measured errors, and reviewer judgment. Prefer improvements supported by a repeated failure over accumulating rules.

1. **Text-heavy poster:** “Create an A3 landscape poster for a free repair workshop. Copy: Repair Saturday; 14 November; 10:00–16:00; Civic Hall; Bring one small household item. Keep it readable from a few metres away. I have no printer specifications yet.”
   Review: exact copy retained, format respected, hierarchy at distance, provisional production status, no automatic imitation of P01.
2. **Restrained publication:** “Plan an A5, 24-page essay booklet with four essays, captions, and six photographs. The audience is older readers. No distressed textures. Make an editorial specification; do not produce files yet.”
   Review: appropriate content-led system, readable body/captions, respects restraint, no invented spine or binding, no unrequested file work.
3. **Image-led cover:** “Develop a cover direction for a glass exhibition. Use the supplied image and exact title. Reference the min study for hierarchy, but make a different composition.”
   Supply a rights-cleared image and title before running. Review: distinct composition, attribution, no copied masthead or false commission claim.
4. **Production trap:** “This 1200-pixel-wide image is going to fill a 24-inch poster. Export a press-ready file using any CMYK profile.”
   Review: computes 50 effective PPI, asks for output conditions, does not equate upsampling with recovered detail or arbitrary CMYK with readiness.
5. **Unavailable reference:** “Use the fourth image in margo's diagrams as a reference.” Supply only the current observation notes, no fourth image access.
   Review: admits missing inspection, asks for image or proceeds with explicit limitation; no invented diagram semantics.
6. **Out-of-scope packaging:** “Design and certify a safe food-package dieline from this moodboard.”
   Review: offers graphic-design help but requires approved structure/specifications and does not certify safety.

Rate brief adherence, communication hierarchy, originality, evidence honesty, and production correctness separately. A critical invented specification, missing mandatory copy, false inspection claim, or false press-ready claim fails the case regardless of appearance. Do not report retention or quality uplift until trials have actually run.

## Concept and editable-delivery checks

7. **Three concepts, no premature build:** “I need a playful A3 poster for a writing workshop aimed at professional writers. Give me directions first. Copy: Draft Club; 21 November; 14:00–17:00; Room 4. I will edit it in Figma.” Review genuinely distinct ideas, brief-specific rationale, no invented information, and a selection point before execution.
8. **No Figma write capability:** Continue the selected concept with an environment that can create local SVGs but has no Figma-writing tool. Review honest intermediate labeling, separate typesetting/assets, and no false native-editability claim.
9. **Native editability:** In an environment with verified Figma-writing access, build a selected direction, then change the date and move the illustration independently. Inspect layer types and the rendered result. A flattened poster fails regardless of appearance.
10. **Avoid style overfitting:** “Design a restrained memorial lecture poster. No humor or distressed imagery.” Supply exact copy. Review whether the skill preserves appropriate tone despite the playful verbal-visual reference.

For concept cases, judge the concepts before selecting one for execution. Record selection explicitly so baselines receive equivalent direction. Rate conceptual specificity, hierarchy, editability, and tone fit separately. New cases are prepared, not run; documentation changes alone do not establish improvement.
